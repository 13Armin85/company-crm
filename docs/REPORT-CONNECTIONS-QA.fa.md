# اتصال گزارش‌ها به بخش‌های نرم‌افزار

## اتصال داده‌ها

گزارش‌ها دادهٔ مبدأ را در هر اجرا دوباره می‌خوانند؛ برای یکپارچه‌سازی، رکوردهای قدیمی جابه‌جا یا کپی نمی‌شوند. گزارش ذخیره‌شده و خروجی فایل نیز از همین مسیر اجرا استفاده می‌کنند.

| ---------------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

تعداد منابع گزارش پایه اکنون ۱۳ است. جدول هر منبع، از جمله سه منبع جدید، در طراحی فرم و جدول‌ها قابل تنظیم است. مسیرهای مجاز بخش‌های مرتبط در صفحهٔ گزارش نشان داده می‌شوند؛ از صفحات عدم حضور و درخواست مرخصی نیز پیوند مستقیم به گزارش یکپارچه وجود دارد.

## تازه‌سازی و دسترسی

- موفقیت هر عملیات ذخیره در فرم‌های اصلی یا سفارشی، نتایج گزارش را نامعتبر می‌کند تا گزارش بازشده دوباره خوانده شود.
- تغییر عدم حضور یا مرخصی، زمینهٔ گزارش روزانه، گزارش تیم، تقویم و ویجت‌های مرتبط را تازه می‌کند.
- گزارش بازشده هنگام بازگشت به پنجره و هر ۶۰ ثانیه تازه می‌شود؛ دکمهٔ «به‌روزرسانی گزارش» نیز دارد و تعریف انتخاب‌شده را حفظ می‌کند.
- مجوز گزارش جای مجوز بخش مبدأ را نمی‌گیرد. دادهٔ عدم حضور از همان محدودهٔ سازمانی مدیریت عدم حضور، داده‌ها از `record_queryset`، پروژه‌ها از عضویت مجاز و تیکت‌های درگاه از دسترسی تیکت خوانده می‌شوند.
- عنوان رکوردهای داده و رابطه‌ها از مسیر مشترک `EntityQuery` خوانده می‌شود؛ فیلدهای مخفی، محرمانه و محدود به نقش یا شرط، از این مسیر نیز افشا نمی‌شوند. شناسهٔ عمومی رکوردهای بومی مانند پروژه نیز در رابطه‌ها رعایت می‌شود. تست دادهٔ عادی و عنوان مخفی/محرمانه و گزارش رابطهٔ مشتری موفق بود.
- عنوان «مدت (روز/دقیقهٔ کاری)» برای مدت محاسبه‌شدهٔ درخواست مرخصی حفظ شده است. برای عدم حضور مستقیم، طول بازه با دقیقهٔ تقویمی نمایش داده می‌شود و به‌عنوان زمان کاری جمع نمی‌شود.
- پایان تاریخی عدم حضور از انتهای بازه و زمان ثبت وضعیت پایان‌یافته محدود می‌شود؛ نسخه و سند امضاشدهٔ درخواست مرخصی تغییر نمی‌کند.

## بررسی‌ها

- مجموعهٔ گزارش و گزارش روزانه: ۷۲ تست؛ یک خطای کمبود حافظه در آماده‌سازی WhiteNoise هنگام اجرای اول، با اجرای مجدد تست CSV برطرف شد.
- تست‌های جدید اتصال: ۱۴ سناریوی موفق شامل ثبت از API، عدم حضور مستقیم، لغو، پایان، پایان زودهنگام مرخصی متصل، اجتماع بازه‌ها، نسخهٔ فعلی درخواست، مجوز و محدوده، پروژهٔ بدون کار، دادهٔ بدون تیکت، صف درگاه، طراحی جدول، گزارش ذخیره‌شده و CSV. سه تست پس از اصلاح دادهٔ اولیهٔ آزمون دوباره موفق شدند؛ مجموع تست‌های متمایز بک‌اند ۸۶ است.
- تست رابط و کش: ۳۰ تست موفق؛ TypeScript وب موفق.
- مرورگر محلی: اجرای موفق هر ۱۳ منبع با API واقعی، ثبت یک عدم حضور آزمایشی، دیده‌شدن همان رکورد دقیقاً یک بار در گزارش، تغییر زمینهٔ گزارش روزانه، پایان از رابط و تازه‌شدن گزارش کش‌شده، نمایش موبایل و دکمهٔ تازه‌سازی. رکورد آزمایشی در محیط توسعه پایان یافت.
- گزارش و تصاویر مرورگر: `tmp/report-connections-browser/`.

## انتشار و بررسی سرور

- آدرس فعال: http://192.168.10.20/reports
- نسخهٔ نهایی: `/home/plane/company-crm-releases/release-20261115-report-connections-v2`
- تصاویر وب و API: `company-crm-web:release-20261115-report-connections-v2` و `company-crm-api:release-20261115-report-connections-v2`؛ worker و beat-worker هم از همان تصویر API استفاده می‌کنند.
- بررسی Django، نبود migration اجرا‌نشده و نبود تغییر مدل موفق بود؛ migration جدیدی اجرا نشد.
- تطبیق SHA256 هر ۹۱۸ فایل اجرایی API و ۱۵۳ فایل وب موفق بود. داده‌های موجود در ۱۵ جدول اصلی و Volumeهای پایگاه داده و فایل‌ها حفظ شدند.
- پشتیبان تازهٔ پایگاه داده و فایل‌ها: `/home/plane/plane-backups/20261115-report-connections-v2`؛ صحت هر دو فایل با `SHA256SUMS` تأیید شد. نسخهٔ پشتیبان مرحلهٔ قبل نیز در `20261115-report-connections` موجود است.
- وب و API سالم و سرویس‌های پشتیبان در حال اجرا هستند. مسیرهای اصلی، مدیریت، spaces، live و درگاه مشتری HTTP 200 دادند.
- ۷ بررسی مرورگر سرور موفق بود؛ هر ۱۳ منبع با دادهٔ واقعی اجرا شد. گزارش مرخصی در بازهٔ پیش‌فرض ۳ عدم حضور موجود را نشان داد؛ تطبیق با شناسه‌های بخش عدم حضور و نبود تکرار بررسی شد و یکی از همان رکوردها از گزارش در فرم اصلی باز شد.
- صفحات داده‌ها، پروژه‌ها و درخواست‌های درگاه، ثبت سه جدول جدید در طراحی فرم و جدول‌ها، پیوند برگشت از عدم حضور به گزارش و نمایش موبایل بررسی شدند. خطای JavaScript یا پاسخ HTTP ناموفق مشاهده نشد.
- برای بررسی سرور هیچ رکورد کاری یا حساب آزمایشی ساخته نشد. نشست کوتاه‌مدت بررسی و فایل‌های احراز هویت موقت پس از تست حذف شدند.
- نتیجه و تصاویر مرورگر سرور: `tmp/report-connections-production/`؛ لاگ‌های ساخت، بررسی داده و سلامت در پوشهٔ نسخهٔ سرور نگهداری می‌شوند.

فرمان مشاهدهٔ سرویس‌ها:

```bash
cd /home/plane/company-crm-current
sudo docker compose -p plane-production --env-file .env.production -f release.compose.json ps
```
