# صفحه‌بندی گزارش روزانهٔ تیم

## قرارداد API

`GET /api/workspaces/{slug}/daily-reports/team/`

| پارامتر     | رفتار                                                                                                        |
| ----------- | ------------------------------------------------------------------------------------------------------------ |
| `date`      | روز گزارش، با همان اعتبارسنجی و منطقهٔ زمانی تقویم فضای کاری                                                 |
| `page`      | شمارهٔ صفحه از ۱؛ مقدار نامعتبر یا منفی به ۱ برمی‌گردد و شمارهٔ بیش از آخرین صفحه به آخرین صفحه محدود می‌شود |
| `page_size` | یکی از ۱۰، ۲۵، ۵۰ و ۱۰۰؛ پیش‌فرض و جایگزین مقدار نامعتبر ۲۵ است                                              |
| `filter`    | یکی از `all`، `missing`، `late`، `submitted` و `not_required`؛ پیش‌فرض `all` و مقدار ناشناخته خطای ۴۰۰ است   |

پاسخ، `people` همان صفحه و اطلاعات `count`، `page`، `page_size` و `pages` را برمی‌گرداند. حتی بدون پارامتر `page` نیز تعداد افراد پاسخ محدود است.

- `count` تعداد کل افراد بعد از اعمال فیلتر است.
- `summary` همیشه آمار کل تیمِ مجاز در همان روز است و با تغییر صفحه یا فیلتر کم نمی‌شود.
- فیلتر «ثبت‌نشده» شامل پیش‌نویس و بدون گزارش است؛ «ثبت‌شده» شامل ثبت عادی و دیرهنگام؛ «لازم نیست» شامل مرخصی/عدم حضور تمام‌روز و روز غیرکاری است.
- ترتیب سرور: بدون گزارش، پیش‌نویس، دیرهنگام، ثبت‌شده، لازم نیست، غیرکاری، آینده؛ سپس نام و شناسهٔ ثابت شخص. نام‌های برابر باعث تکرار یا حذف ردیف بین صفحه‌ها نمی‌شوند.
- `empty` تنها برای نبود زیرمجموعه در دامنهٔ مجاز پر می‌شود. فیلتر بدون نتیجه، پیام مخصوص فیلتر را نشان می‌دهد و آمار تیم را نگه می‌دارد.

## دامنهٔ دسترسی و هزینهٔ خواندن

مجوز `DailyReport.Team.View` یا `Report.ViewAll` و دامنهٔ سازمانی و جانشینی همان سرویس مشترک گزارش‌ها اعمال می‌شود. خود بیننده از فهرست تیم حذف می‌شود و پارامترهای صفحه‌بندی دامنه را گسترش نمی‌دهند.

برای محاسبهٔ وضعیت و آمار، تقویم، مرخصی، عدم حضور و سربرگ گزارش افراد مجاز به‌صورت گروهی خوانده می‌شود. متن آیتم‌های گزارش و مشخصات تیکت‌ها فقط برای افراد صفحهٔ انتخابی خوانده و آمادهٔ پاسخ می‌شود؛ آیتم‌های حذف‌شده در شمارش و جزئیات نمی‌آیند. منابع گزارش‌ساز و یادآوری‌ها همچنان جزئیات کامل موردنیاز خود را دریافت می‌کنند.

## رابط کاربری و آزمون

جدول فقط ردیف‌های پاسخ سرور را نمایش می‌دهد. کنترل مشترک صفحه‌بندی، تغییر تعداد ردیف، صفحهٔ قبل/بعد و اول/آخر را ارائه می‌کند. با تغییر روز، وضعیت یا تعداد ردیف، صفحه به ۱ برمی‌گردد. اندازهٔ صفحه در مرورگر برای همین جدول نگه داشته می‌شود. روز، فیلتر، شماره و اندازهٔ صفحه همگی در کلید کش و درخواست API حضور دارند.

آزمون‌های مرتبط:

- `apps/api/plane/tests/contract/app/test_team_daily_pagination.py`: تیم ۳۱ نفره، چهار صفحه، ترتیب پایدار، نبود تکرار، محدودبودن کوئری جزئیات به صفحهٔ جاری، آمار، فیلترها، دسترسی و ورودی نامعتبر.
- `apps/web/app/crm/daily-report/daily-report.test.tsx`: نمایش آمار و کنترل صفحه‌بندی با اعداد سرور، ترتیب پاسخ و فیلتر بدون نتیجه.
- `apps/web/tests/browser/crm-team-pagination.mjs`: تعامل مرورگر با API واقعی در محیط توسعه؛ بدون ایجاد یا ویرایش داده.

تغییر ساختار پایگاه داده و migration لازم نیست.

### نتیجهٔ اجرا — ۲۰۲۶/۱۱/۱۶

- هر ۷ آزمون API مرتبط با صفحه‌بندی، دسترسی و دامنهٔ تیم موفق بود. بررسی UUID در کوئری با هر دو نمایش دارای خط تیره و بدون آن سازگار شد و تست مربوط دوباره پاس شد.
- هر ۵۰۷ آزمون رابط کاربری CRM و درگاه در ۶۲ فایل پاس شد. پس از اصلاح هشدارهای هوک، ۴۴ آزمون مرتبط دوباره موفق بود؛ این اجرا شامل ۱۷ آزمون گزارش روزانه و تست جدید هویت پایدار ردیف‌های ذخیره‌نشده است.
- بررسی TypeScript موفق و lint سخت‌گیرانهٔ هر ۶۹ فایل جاوااسکریپت و تایپ‌اسکریپت آمادهٔ کامیت، بدون هشدار و خطا بود. سازگاری مرتب‌سازی با هدف ES2022 برنامه حفظ شد.
- هر ۶ بررسی مرورگر با API واقعی موفق بود: صفحهٔ دوم، فیلتر سمت سرور، صفحهٔ آخر، تغییر روز، تغییر تعداد ردیف و نمای ۳۷۵ پیکسلی با چند صفحه. خطای جاوااسکریپت ثبت نشد.
- محیط موقت تست پس از اجرا پاک‌سازی شد.
